# Scripture Study — Bible Study PWA

## What This Is
A desktop-first Progressive Web App for serious Bible study. Offline-first, zero-dependency, vanilla JavaScript. SQLite via sql.js (WebAssembly). No framework, no build step, no bundler.

## Architecture
- Single HTML page (index.html) with ES modules
- SQLite databases accessed via sql.js:
  - data/core.db — books, cross-references, Nave's topics; on first run it's copied to OPFS and the user-data tables (notes, tags, bookmarks, markups, plans) are added there
  - data/translations/*.db — one per translation (KJV, ASV, WEB, YLT, BSB installed by default; Darby an add-on). data/translations/catalog.json lists them all with sha256, size and verse count; scripts/build_catalogs.py regenerates it (and data/reference-catalog.json, for language.db and lexicon-hebrew.db) after any rebuild of a shipped file; the --ship builds run it themselves. core.db's `translations` table means "installed on this device"
  - data/language.db — original-language words, Greek lexicon (TBESG), Greek and Hebrew morphology (TEGMC, TEHMC), Hebrew word pieces and Ketiv/variants; read-only; downloaded to OPFS in the background after launch, opened only when the Language tab or a titled Psalm needs it; built by scripts/build_language.py (`--ship` to copy to data/; decisions in docs/HEBREW_ANATOMY_DATA_REPORT.md)
  - data/lexicon-hebrew.db — Hebrew lexicon: Strong's, Brown-Driver-Briggs, and the links between them ranked by OSHB word counts; read-only; downloaded in the background like language.db, opened only on the first Hebrew Lexicon tap; built by scripts/build_lexicon_hebrew.py from pinned, sha256-checked Open Scriptures sources, byte-identical on rebuild (`--ship`; decisions in docs/HEBREW_LEXICON_REPORT.md). After a rebuild, an install replaces its copy in the background on its next online launch (the catalogs' sha256 changed) and uses it from the launch after
- OPFS for persistent storage, IndexedDB as fallback; writes go through a storage worker
- Installed data files update themselves: after launch, online, checkForDataUpdates() in db.js replaces any translation, language.db or lexicon-hebrew.db whose sha256 differs from its catalog entry. Which version each file is, is recorded per machine in localStorage (`ember.installedFiles`), never in core.db, since backups move between machines
- Service worker for offline caching
- CSS custom properties for theming (light + dark)

## Code Style
- Vanilla JavaScript, ES modules (import/export)
- No frameworks, no build tools, no bundlers
- Functions over classes where practical
- Descriptive variable names, no abbreviations
- CSS custom properties for all colors and key dimensions

## Key Technical Details
- Verse IDs use BBCCCVVV format, stored as integers (e.g., 1001001 = Genesis 1:1; 43001001 = John 1:1). Psalm titles are verse 0.
- db.export() + saveToStorage() after every write operation to core.db
- sql.js does not enforce ON DELETE CASCADE — delete child rows explicitly
- sql.js has no FTS5 module: translations' verses_fts and core.db's notes_fts are FTS4. Search input goes through searchMatchExpression() in db.js, never straight to MATCH
- Note anchors use range-aware queries through anchorsOverlapping() in db.js — see docs/ANCHOR_QUERIES.md
- notes_fts is external-content: delete from it before changing a note's body in `notes`, never after
- USER_MANUAL.md is shown in the app as the help guide. A change that alters what the user sees isn't finished until the manual (and the panel's help popover, if it applies) says so. sw.js precaches the manual, so bump CACHE_NAME when it changes, and keep every `data-help-section` in index.html naming one of its headings (`python3 tests/verify.py help` checks). A new control the manual mentions gets a `data-help-target` and an entry in help-map.js's target table; the manual points at it with a map link, `[text](#section "map:name")`
- `.note-block` uses content-visibility: auto. In a skipped block, innerText is empty and overflow is clipped, so read a note's text at input time (see scheduleSave in js/notes.js). Update a block in place rather than rebuilding the study, or the scroll position moves
